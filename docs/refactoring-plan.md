# linker のリファクタリング・修正計画

## 目的と担当

GitHub から取得した利用者が導入・操作でき、設定・実リンク・管理 DB が
不一致になった場合も、安全に検出・復旧できるツールにする。

- コード実装は Luna が担当する。
- 親エージェントは仕様整理、作業分割、実装結果のレビューを担当する。
- 計画の協議を終え、ユーザーから実装開始の指示を受けている。
- 構造変更と動作変更を別の変更単位に分ける。
- 実モデル・運用先ディレクトリ・運用 DB を試験に使わない。
- 各段階の成果物と検証結果をレビューしてから、依存する次の作業へ進む。

## 合意済みの方針

| 項目 | 方針 |
| --- | --- |
| 対応 OS | GNU/Linux |
| 未管理リンク | sync 時に設定どおりなら登録する。異なるリンクは変更・削除せず衝突として報告する |
| 管理済みリンクの手動変更 | 実リンクが DB の記録と異なる場合は停止・報告する |
| 設定によるリンク元変更 | 実リンクが DB の記録と一致する場合に、設定どおり付け替える |
| 互換性 | 標準入力からの呼び出しと既存の設定項目を維持する。既定 DB 保存先変更・移行は別の変更として扱う |
| lookupKeys | 必須。1 件以上のカテゴリ名を要求する |
| YAML | Spyc を Symfony YAML に置き換える |
| CLI の追加範囲 | ヘルプ、dry-run、カテゴリ指定 |
| GitHub Actions | ユーザー指示により導入しない。準備した workflow は撤去する |
| 開発用チェック | PHPStan、PHP 構文検査、PHP-CS-Fixer を導入し、プロジェクト全体に適用する |
| 今回の対象外 | glob、リンクの別名指定、設定から消えたリンクの自動削除 |
| 事前検証の失敗 | 選択対象に問題が 1 件でもあれば、リンク・管理 DB を変更せず全体を終了する |
| 実行中の失敗 | 以降の処理を停止し、完了済み・失敗・未実行を報告して非ゼロ終了する。全体の自動巻き戻しは今回の保証に含めない |

通常ファイル・ディレクトリの保護、壊れたリンクへの対応、失敗時の非ゼロ終了は
計画の基本要件とする。

## 段階 3: 設定検証と操作計画

### 実装範囲

処理を「読込 → 設定検証 → 対象選択 → 操作計画・事前検証 → 実行」に分ける。

- グループの meta.enabled、baseDirectory、weightsList、ignoreList の型と必須性を定義する。
- ignoreList の省略は空配列として扱い、現在の設定項目を維持する。
- 作成対象のリンク元と親ディレクトリを検証する。
- 削除では元ファイルの存在を要求しない。対象が既に存在しない場合も扱えるようにする。
- 通常ファイル・ディレクトリの衝突、同じリンク先への異なる操作を検出する。
- パスの別表記・親ディレクトリの symlink・相対リンク元の比較方法を定義する。
- リンク元そのものの削除や、destination の外への操作を防ぐ。
- 事前検証が失敗した場合は、DB の新規作成・スキーマ初期化も行わない。
- DB 読み取りと DB の作成・更新を分離する。

### 完了条件

正常項目の後ろに衝突や欠落がある設定でも、リンク・DB が変更されずに失敗する。
設定の並び順を変えても、同じ衝突を検出する。

## 段階 4: 安全な同期・解除と DB 整合性

### 状態ごとの期待動作

| 実体 | DB | 期待動作 |
| --- | --- | --- |
| 通常ファイル・ディレクトリ | 有無を問わない | 変更・削除せずエラー |
| 対象なし | 記録なし | sync では作成・登録、clear では変更不要 |
| 対象なし | 記録あり | sync では再作成・記録更新、clear では記録削除 |
| 設定どおりのリンク | 記録なし | sync ではリンクを維持して登録、clear では未管理として拒否 |
| 設定と異なるリンク | 記録なし | sync / clear とも衝突として拒否 |
| 実リンク・記録・設定が一致 | 記録あり | sync は変更不要、clear は解除・記録削除 |
| 実リンクと記録は一致し、設定だけ異なる | 記録あり | sync は付け替え・記録更新、clear は解除・記録削除 |
| 実リンクが記録と異なる | 記録あり | 設定と一致する場合も手動変更として拒否 |
| 壊れたリンク | 記録あり | リンク先表記と記録を比較し、管理対象として確認できるものを解除・修復 |
| 壊れたリンク | 記録なし | sync は元ファイル欠落または衝突として失敗、clear は未管理として拒否 |

sync の作成・維持対象で元ファイルが欠落している場合は事前検証に失敗する。
clear と sync の削除対象では元ファイルの存在を要求しない。

### 設定との対応を維持する事項

- sync: 有効グループの weightsList を作成・維持する。
- sync: 有効グループの ignoreList と、無効グループの weightsList を解除対象にする。
- sync: 無効グループの ignoreList は現在の扱いを維持し、処理対象に追加しない。
- clear: 有効・無効を問わず weightsList と ignoreList を解除対象にする。
- clear は設定を書き換えず、設定から消えた項目も自動探索・削除しない。

### 実装範囲と完了条件

- 対象レコードの有無だけでなく、記録された source を取得して比較する。
- レコード登録・更新を再実行可能にし、欠落リンクの修復で一意制約エラーを起こさない。
- DB とファイルシステムの失敗を別々に検証し、変更済みの実体を正確に報告する。
- 正常な設定は 1 回の sync で期待状態になり、2 回目は不要な変更を起こさない。
- 失敗時も元ファイルが保たれることを検証する。

## 段階 5: CLI・結果・実行時の失敗

### 実装範囲

- --help、--dry-run、繰り返し指定できる --category を追加する。
- --category は lookupKeys の範囲をさらに絞り、範囲外の指定は引数エラーにする。
- dry-run と本実行は同じ計画・事前検証を使う。
- dry-run はリンク・管理 DB を変更せず、DB が存在しなくても新規作成しない。
- 作成・付け替え・登録・解除・変更不要・失敗・未実行を識別できる結果にする。
- 異常がある場合の非ゼロ終了と、不正な引数の診断を実装する。
- 同じ管理対象に対する同時実行を排他し、実行直前にも前提状態を確認する。

### 実行中失敗の方針（合意済み）

修正前の実装にも失敗ログと一部のエラー集計はあったが、全体停止の仕様は統一されていなかった。
リンク作成・記録登録の失敗はカウンターを増やして戻るため、実行ループは次の項目へ進む。
解除失敗は UnlinkOperation でエラー集計されない場合がある。
未捕捉例外では処理が中断するが、通常の集計表示には到達しない。
結果クラスには未実行件数がなく、CLI も集計上の失敗を終了コードへ反映していない。
追加するのは、これらを統一した停止・部分結果報告・終了コードの仕組みである。

事前検証を通過した後にリンク操作や DB 更新が失敗した場合は、以降の実行を止め、
完了済み・失敗・未実行を報告する。処理全体の自動巻き戻しは今回の保証に含めず、
失敗した操作内での復旧範囲は段階 4 の設計で明示する。

事前検証の失敗時に全体を変更しないという合意と、実行中の障害時の扱いを区別する。

### 完了条件

プレビューどおりの対象だけが処理され、失敗・中断を成功扱いしない。
dry-run の前後でリンクと DB の内容・存在状態が変わらない。

## Luna への実装依頼とレビュー

各依頼では、対象段階・変更してよい範囲・維持すべき挙動・完了条件を渡す。
最初の依頼は段階 1 に限定する。レビューで、構造変更に安全性修正や機能追加が
混ざっていないことを確認する。

各段階の報告には、変更内容・検証結果・未解決事項を含める。
共有作業ツリーの既存変更を破棄せず、コード変更が競合する段階を同時に実装しない。

実装時に具体化した詳細:

- --category は lookupKeys 内の絞り込み。対象順は lookupKeys の順を維持する。
- 終了コードは成功 0、設定・事前検証・実行失敗 1、引数エラー 2。
- リンク元の同一性は相対 readlink を対象の親から解決して比較する。
  実在するパスは realpath を用い、壊れたリンクでは実在する親と残りのパスを解決する。
  symlink と .. が混在するパスを、参照先を解決する前に文字列だけで畳まない。
- destination 自体の symlink は許容し、その配下の相対パスが外へ逸脱する場合を拒否する。
- 同じ管理 DB を使う実行は排他し、操作直前に計画の前提状態を再確認する。
- 失敗した操作の途中まで効果が生じた場合は、その対象と効果を報告する。
  全体の自動巻き戻しは行わず、実体と記録の確認に必要な情報を残す。

これらは合意済みの安全方針・機能範囲を実装に落とし込むための詳細であり、
新しい操作範囲や自動削除機能を追加するものではない。
